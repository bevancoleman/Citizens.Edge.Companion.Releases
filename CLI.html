Citizen's Edge Companion

Companion command-line reference

ce-companion <command> [options]. The WebSocket API is docs/PROTOCOL.md. Org sync, which the sync command drives, is docs/ORG-SYNC.md. The summary, options and command text below are generated from crates/ce-cli/commands.json, the same file --help and the shell completions read.Change the JSON, then this page.

How a command runs

  • Exit codes: 0 ok, 1 command error, 2 usage error.
  • With the Companion running (ce-companion start or daemon), commands run inside it over the local control socket (Unix socket; Windows named pipe, protected by filesystem permissions), on its own low-priority queues, through the same handlers as the matching WebSocket message. A command and its message do the same thing.
  • Without it, commands open companion.db directly. The offline reads (status, captures, logs, ocr-report, models, contacts aliases, truth stats|queue|history) open it read-only.
  • One Companion per data folder: start, daemon, demo and client are standalone; a second start finds companion.lock (an exclusive file lock holding the pid) or a listening socket and exits.
  • Heavy work waits for the game. Commands marked heavy (OCR re-reads, cleanup, maintenance) are held while Star Citizen runs; --now or --force overrides where the usage text says so.
  • --json prints a machine-readable result on commands marked --json.
  • Confirmation: commands marked confirms ask first on a terminal; --yes skips the question and is required without one; --dry-run shows the plan and changes nothing.
  • Output is plain text without colour or spinners unless stdout is a terminal.

Environment: CE_ENV (selects the environment), CE_SC_CHANNEL (the Star Citizen channel), CE_UPDATE_URL and CE_UPDATE_CHANNEL (the release feed), CE_REPORT_REPO (where crash reports are filed).

reevaluate

reevaluate Re-evaluate every derived result after a code change: re-parse all logs (backfill --full), re-run OCR on saved captures (backfill --captures),
           run `truth check --full`, re-check the confirmed truth against the new rows (moved / stale / orphaned), remove stale derived data, then print truth stats
           and the doubtful-queue size. Slow (about 2.6 s per capture, plus the check)
           reevaluate [--kind <kind>] [--dry-run] [--yes]
             --dry-run   print the plan, the warning and the stale-data counts; change nothing and never ask
             --yes       skip the confirmation question (the warning is still printed); without a terminal it is required
           Removed: unconfirmed truth rows whose capture or row no longer exists, derived OCR files (detections, row crops) whose capture is gone.
           Reported only: unconfirmed truth rows the machine now reads at another row index, captures still without sidecar v2.
           Never touched: captures and images, confirmed truth values.

Flags: --kind, --dry-run, --yes, --json, --golden, --corpus, --now, --sc-dir, --channel, --full-desktop, --ocr-threads

truth

truth      Ground truth for commodity terminal OCR: review, confirm, export a golden set, check for regressions
           truth queue [--limit n] [--json]     unconfirmed rows, most doubtful first (disagreeing reads, single reads, unchecked price, held back), with a row crop PNG
           truth crop refresh <truth-id> [--raw]  regenerate a row crop (also accepts <capture> <row>; available at the crop URL with ?refresh=1)
           truth confirm <truth-id> [--price n] [--quantity n] [--status text] [--name text]
                                                confirm a row as read, or with the corrections given; the queue also accepts <capture> <row>
           truth confirm --all-agreed [--yes]   confirm every row whose fields all have 2+ agreeing reads and no disagreement (prints the count; --yes does it)
           truth unconfirm <truth-id>          take a confirmation back (also accepts <capture> <row>)
           truth report <truth-id> <needs-reprocessing|bad-crop|unreadable> [--note text]
                                                save evidence for local agent investigation; remove from confirmed truth without deleting the sample
           truth reports [--all] [--json] [--out <dir>]
                                                active reports (all includes resolution history); --out exports reports.json, original captures and detections for agents
           truth resolve <truth-id> --note text  record investigation findings and return the row for review, without confirming it
           truth stats [--json]                 confirmed vs unconfirmed, machine accuracy against the truth, coverage by resolution / UI scale / terminal type
           truth export --out <dir>             write the confirmed rows as golden cases (row crop PNG + JSON label each) under <dir>/cases
           truth import [dir]                   load a golden folder's labels back into the truth table (default tests/golden/commodity)
           truth check [--golden <dir>] [--full] [--update-baseline [--force]] [--json]
                                                re-read the golden cases with the current OCR (fast: the crops; --full: the original captures) and compare with baseline.json;
                                                exits 1 when a previously right case turns wrong or accuracy drops; appends a line to history.jsonl;
                                                --full reads the originals from the regression corpus when it is present (else from the data dir)
           truth history [--json] [--last n] [--golden <dir>]
                                                the check runs from history.jsonl: whole-row accuracy per run (change against the previous run of the same tier), per terminal type and window size,
                                                commit and parser version; REGRESSION marks a drop of more than 2 points overall or in a group
           truth corpus sync|verify [--golden <dir>] [--corpus <dir>]
                                                sync: copy the original captures behind the golden rows (PNG + sidecar) into the regression corpus outside git
                                                (~/GitHub/Citizens.Edge/ocr-reference/regression/<terminal type>/) and write tests/golden/corpus-manifest.json;
                                                verify: check every manifest image exists there and still has its sha256

Flags: --limit, --json, --price, --quantity, --status, --deep, --name, --note, --all, --out, --golden, --corpus, --last, --all-agreed, --yes, --update-baseline, --force, --full, --raw, --now, --sc-dir, --channel, --full-desktop, --ocr-threads
